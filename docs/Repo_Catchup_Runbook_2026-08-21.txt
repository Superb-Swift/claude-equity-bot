JOB B — THE HISTORY REWRITE. DESTRUCTIVE. READ ALL OF IT FIRST.
=============================================================================

WHAT IT DOES        Purges tracker_with_registry.xlsx from every commit in the
                    repository's history, then force-pushes the rewritten
                    history over origin/main.

WHAT IT COSTS       * Every commit SHA after the first touch of that file
                      changes. Any existing clone or fork is broken and must
                      be re-cloned. If nobody else has cloned it, this costs
                      nothing.
                    * Open pull requests and issue links to specific commits
                      will break.
                    * GitHub keeps unreachable objects cached for a period and
                      may still serve them by direct SHA URL. To purge those
                      fully you must ask GitHub Support to run gc on the repo,
                      AFTER the force-push lands. The rewrite alone is not the
                      whole job.

WHAT IT DOES NOT    The file is not a credential — no rotation is needed. It is
NEED                personal trading data, so the remediation is removal and
                    reduced discoverability, not key rotation.

  --- B.1  Install the tool (git filter-branch is deprecated; do not use it)
      pip install git-filter-repo

  --- B.2  Work on a FRESH CLONE. filter-repo requires a clean, freshly-cloned
           copy and will refuse otherwise. Never run it on your working folder.
      cd C:\Users\rober
      git clone https://github.com/Superb-Swift/claude-equity-bot.git ceb-rewrite
      cd ceb-rewrite

  --- B.3  Confirm the files are actually in history before purging them
