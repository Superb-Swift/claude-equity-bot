REM ===========================================================================
REM STEP 6 — RECOVERY: only if `git push` is rejected with "fetch first"
REM ===========================================================================
REM Cause: origin/main has a commit you don't have locally (web edit / other
REM machine). If you ALSO have unstaged changes (e.g. tracker_with_registry.xlsx),
REM a plain `git pull --rebase` errors with "cannot pull with rebase: unstaged
REM changes" — so stash first. Full dance:
REM
REM   git stash
REM   git pull --rebase origin main
REM   git push
REM   git stash pop
REM
REM Notes:
REM   - `git stash` parks unstaged changes safely; `git stash pop` restores them
REM     after the rebase (your tracker edits survive untouched).
REM   - If `git stash pop` reports a conflict, your data is still in the stash:
REM       git stash list          (confirm it is there)
REM     resolve the file, `git add <file>`, then it is done. To bail out of a
REM     mid-rebase entirely: git rebase --abort
REM   - The LF/CRLF warnings during add/stash are cosmetic (git normalizing line
REM     endings on Windows) — safe to ignore.
